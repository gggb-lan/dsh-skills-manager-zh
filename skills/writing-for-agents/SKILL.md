任何会被代理读到的文档——技能、`AGENTS.md` / `CLAUDE.md`、由指针指向的文档——都适用同一套写法。包装形式不同，写法相同：代理每次运行都会走同样的**过程**，而不是产出同样的结果，所以同一批杠杆能让它们变得可预测。

如果你写的是一份技能，先读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式与路由型技能。

## 上下文指针

**上下文指针**是留在代理上下文里的一条引用：它点名某个上下文之外的材料，并编码“什么条件下该去取它”。技能的 description 是一种，`AGENTS.md` 里指向某份文档的一行也是同一种东西。决定代理在什么时候、以多高可靠性去取材料的，是**指针的措辞**，不是目标本身。必备材料配了一句软绵绵的指针，就是方差 bug：先把措辞改锐，实在不行才把内容内联。

指针干两件事：说明材料是什么，以及列出应当触发它的**分支**（分支指文档能处理的不同情形，不同运行会走不同路径）。常驻的指针每个字在每一轮都要付费，所以它比正文更需要狠心删减：

- **把关键词前置**：指针就是它触发工作的位置。
- **每个分支一个触发词**。同一个分支的同义词只是把同一分支写了两遍；合并它们，只留真正不同的分支。
- **删掉正文已经承载的身份信息。**

## 两种负载

你添加的每份文档和指针，都在花两种预算之一：

- **上下文负载**：常驻材料对代理窗口的占用——一行 `AGENTS.md`、一条技能 description、任何每轮都躺在上下文里的东西。无论是否触发，都在消耗 token 与注意力。
- **认知负载**：落在人身上的成本——有哪些文档、什么时候该用哪一份。人就是索引。这不是要尽量压低的成本，而是人类主体性的代价：在需要人判断的地方花它，在不需要的地方去掉它。

只靠指针抵达的材料，用一行指针的代价换掉了上下文负载；完全没有指针的材料，则完全压在认知负载上。

## 信息层级

文档由两类内容构成：**步骤**（代理按顺序执行的动作）与**参考**（按需查阅的定义、规则、事实）。两者可以自由混合：全步骤（一份食谱）、全参考（一次评审的规则、本技能）、或两者兼有。核心决定是每一块内容放在**信息层级**的哪一层——这是一把按“代理多急需”排序的梯子：

1. **文件内步骤**是主层：代理按顺序做什么。
2. **文件内参考**按需查阅。常常是合法的扁平同层集合（一次评审的每条规则在同一层），这是合理排布，不是坏味道。
3. **外置参考**被推到单独文件，用上下文指针抵达，只在指针触发时加载。范围从同目录的兄弟文件，一直到任意位置、任何文档都能指向的外部参考。

压得太少，顶层会膨胀；压得太多，会把代理真正需要的材料藏起来。这个张力就是全部决策。

**渐进披露**就是沿梯子往下推（移出主文件、藏到指针后），让顶层保持可读。它主要不是 token 优化，而是保护层级的手段。分支是最好的披露判据：所有分支都要用的内容内联，只有部分分支才会用到的内容推到指针后。文档里有步骤时，本该外置的文件内参考会把他们埋没，让“有没有认真看步骤”变成抛硬币——这是方差杠杆，不只是可读性问题。

**就近聚合**是文件内的配套动作：梯子决定一块内容放多深，就近聚合决定到了那一层之后它旁边放什么。把一个概念的定义、规则、注意事项放在同一个标题下，而不是散落各处，这样读其中一部分就会把邻居一起带进来。检验标准：文档应当读起来像“为代理写的文档”。聚合的材料读起来是这样，散落的不是。（这不同于重复：重复是把一个意思写两遍；散落是把一个意思撕成很多片。）

**蔓延**是这里的失败模式：文档单纯太长，即使每一行都有效且唯一。注意力被稀释，每一行都要额外维护。解法还是梯子：把参考推到指针后，按分支或按顺序拆分，让每条路径只携带自己需要的东西。

## 步骤与完成判据

每个步骤都以**完成判据**收尾：告诉代理“做完了”的条件。两个属性让它成为杠杆：

- **清晰度**：代理能否分清做完与没做完？模糊的边界（“理解到位”）会招来**提前收工**：在真正做完前就结束，注意力滑向“看起来做完了”。后面可见的步骤（**后续步骤**）提供拉力，判据的清晰度提供阻力。按顺序防守：**先把边界改锐**（局部、便宜）；只有当它本质上就模糊、**并且**你确实观察到抢跑时，才通过拆序列把后续步骤藏起来。隐藏只在真正的上下文边界上有效（交接或派子代理）；内联调用会让后续步骤仍留在上下文里，什么都清不掉。
- **要求强度**：它要求多少。“每个被改动的模型都有交代”能逼出彻底的工作，“产出一份变更清单”不能。要求强度驱动**深挖**（代理在任务内部做的挖掘，潜藏在措辞里，而不是写成单独一步），而且它不局限于步骤：“每条规则都应用”同样能约束一片扁平参考，就像“每一步都做完”约束一个序列——这也是全参考文档依然能带穷尽性要求的原因。

最强的判据既**可检验**又**穷尽**。

## 什么时候拆分

把一份文档拆成两份，就要花掉两种负载之一，所以只有切分本身能回本时才拆：

- **按序列拆**：当后续步骤会引诱代理草草结束当前步骤时，把一串步骤拆开。让后续步骤不在视野里，会驱动当前任务更多的深挖。反过来要小心：合并序列会让每一步的后续步骤暴露给下一步，招来提前收工。
- **按调用方式拆**，技能专属：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 领词

**领词**（leading word）是一个已经活在模型预训练里的紧凑概念，代理在运行文档时用它来思考（_lesson_、_fog of war_、_tracer bullets_）。它只作为一个 token 反复出现，从不写成整句；它在最少 token 里积累出分布式定义，并靠调动模型已有的先验，锚定一整片行为。自造词也行，但必须先定义清楚；新造词招不到先验，你在定义上付出的 token，正是预训练词免费给你的。优先找现成的词。

它锚定两次。在正文里锚**执行**：每当这个词出现，代理就调用同一套行为；在扁平参考里，它把注意力聚焦到某一类要找的东西上。在指针里锚**调用**：当同一个词同时活在你的提示词、文档和代码库里，代理会把这份共享语言与材料关联起来，从而更可靠地去取它。

主动寻找用领词重构的机会。三个地方各写一遍的三元组、一句花整句去比划一个概念的指针，都是等着被压成一个 token 的段落：

- “快、确定、开销低” → 一个 _紧_（a tight loop）。
- “一个你信得过的循环” → _红_，把模糊的门槛变成二元可观察状态（循环在这个 bug 上变红，或者没变）。

你双赢：token 更少，还给代理一个更锐利的思考挂钩。假设每份文档都带着可被领词替代的复述，去找它们。

**否定式指令**是这条杠杆旁边的失败模式：用禁止来引导，会把被禁行为拖进上下文，让它**更**可得，而不是更不可得。_别去想大象_，结果满脑子都是大象；否定只是一个弱修饰语，会被强激活的概念淹没，禁令反而有一半像在指示你去做。要提示**正面目标**：直接说“写一行注释”，让被禁的行为根本不被提起。禁令只有在无法正面表述的硬护栏里才配得上位置；即便如此，也要配上正面目标，让注意力落在该做什么上。

## 删减

- 每个意思只保留**单一事实源**：一个权威位置，改行为就是改一处。**重复**（同一意思出现在多个地方）同时消耗维护成本与 token，还会把一个意思在梯子上的显眼程度抬到超过它真实的层级。（它恰好是领词的反面：领词是故意重复 token，从不重复意思。）
- **环境**也是事实源（`package.json` 脚本、配置文件、目录结构、`--help` 输出），复述环境的文档是一份**缓存**：一次查找的副本，只有查找足够昂贵时才配得上它的负载。缓存代理查不到的东西：没写下来的约定、某个选择背后的原因、配置从不承认的坑。查一个文件、跑一条命令就能拿到的东西，留给环境，它们不会过期。
- 逐行检查**相关性**：它还与这份文档要做的事有关吗？一行会因为从未与任务相关（纯陈述，或本该外置的分支）而失去相关性，也会因为它描述的行为或世界变化而过期。更短的文档更容易保持相关。没有删减纪律，默认结局是**沉积**：一层层过期内容因为“加着安全、删着危险”而沉下来，直到你不得不从中间钻下去，才能找到还活着的部分。
- 逐句猎杀**空操作**：模型默认就会遵守的指令，花了负载却什么都没说。检验标准是“它相对默认行为是否改变了行为”，这是模型相对的，不是读者相对的：两个人对某句是不是空操作的争论，其实是在争默认行为是什么，靠跑文档来定，不靠辩论。一句话不合格，就删整句，而不是抠掉几个词。这个检验也适用于领词：弱到打不过默认的词（代理本来就算细致，你写“要细致”）就是空操作，修法是换更强的词（“不间断地”），而不是换技术。
