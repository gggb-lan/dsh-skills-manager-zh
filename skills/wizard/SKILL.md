# 向导

**向导**是一个 bash 脚本，一步步带人走完一套手工流程——手工做很繁琐，每次向 AI 重新解释也很繁琐。它打开每个 URL，明确说点哪里、复制什么，捕获这些值，写到该去的地方（`.env`、GitHub secrets），每个阶段都确认，并显示还剩几个阶段。它可能配置第三方服务、跑一次性迁移，或把项目从一个状态搬到另一个状态。

愉快的 UX 已由 [template.sh](template.sh) 解决：分阶段进度、确认关卡、跨平台打开 URL（含 WSL）、隐藏式密钥输入、幂等的 `.env` upsert、`gh secret`/`gh variable` 写入、收尾总结。**你的工作只是界定流程并编写阶段。** `STAGES` 标记以上的库在每个向导里都完全相同，这种一致性就是重点：永远不要手改它。

向导默认是临时的：为一次运行而建，存到临时目录或 `scripts/` 路径，活干完就删。只有用户想要一条可重复、该留在仓库里的配置路径时才提交它。

## 流程

### 1. 界定流程

梳理人必须做的每个手工步骤，以及沿途捕获的每个值。先读仓库，不要空口问：

- 配置类：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置、`.github/workflows/*`（每个 `secrets.*` / `vars.*` 引用都是向导必须产出的值）。
- 迁移或切换类：当前状态、目标状态，以及两者之间不可逆的动作。

然后把有序的阶段列表和每个阶段产出的值给用户看并确认：他们可能增加、删除或重排。

**完成判据：** 每个阶段按顺序命名，且每个捕获的值你都知道：(a) 人从哪里拿到，(b) 写到哪里（`.env`、GitHub secret、两者，或都不写——有些阶段是纯动作），(c) 是否机密（隐藏输入）。

### 2. 画出每个阶段的路径

为每个阶段写出人要走的确切路径：打开哪个 URL、在那里做什么、值显示在哪、填哪个变量，例如“Dashboard → Developers → API keys → Reveal test key → copy”。你并不真正了解当前 UI 或确切命令的地方，说出来并问用户或查文档：绝不编造可能不存在的步骤。

**完成判据：** 每个阶段都能追溯到陌生人可照做的具体指令。

### 3. 编写向导

把 `template.sh` 复制到目标路径。用每个步骤一个 `stage` 替换示例阶段，按依赖顺序。使用库助手：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。把 `TOTAL_STAGES` 设为实际阶段数。

守住模板设定的标准：先打开 URL 再要它的值；任何机密都用 `ask_secret`；每个持久化的值都走 `write_env`；只有 CI 真正需要的值才 `set_secret`；任何不可逆动作之前先 `confirm`。每个 `stage` 会清屏，只显示当前步骤：一个阶段只放一个聚焦任务，别让人需要的东西滚出屏幕。不要碰标记以上的库。

### 4. 验证并交接

- `bash -n <script>`；有 `shellcheck` 就跑一下。
- `chmod +x <script>`。
- 不要自己端到端跑：它会打开浏览器、阻塞在人的输入上。改为静态追踪：第 1 步列出的每个值都被捕获、都落到第 1 步说的位置，每个 `set_secret` 名字都与 CI 里的 `secrets.*` 引用精确匹配。
- 告诉用户怎么运行。如果它是可重复的配置路径，提交它并从 README 链接过去，让下一个人跑脚本而不是问 AI。
